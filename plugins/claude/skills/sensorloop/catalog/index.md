## Loops (32)

- `bug-failing-test-fix`: **A bug starts with a failing test**. The agent turns a bug into a test that fails for the bug's reason, changes the code until it passes, and runs the whole suite. Reads: `test-runner`. When: On every bug fix, before the code is changed and again after.
- `isolated-environment`: **A clean environment for each task**. Each task gets a new environment of its own, which checks its own isolation before the agent starts and is thrown away at the end, so the sensors give the same result for the same code. Reads: `isolation-probe`. When: At the start of each task, before the agent starts; while it works, on every sandbox process; after teardown; and in CI, on every change to the setup files.
- `spec-before-tests`: **A complete spec before the tests**. Each requirement is traced to the spec elements that cover it and the tests that check it, the spec is closed against every gap a test writer would have to guess at, and each functional requirement names the production signal its release is confirmed by. Reads: `requirement-trace`, `spec-completeness`, `human-answer`. When: After every edit to the requirements or the spec, before tests are derived from it; again once the tests are written, and in CI on every pull request that touches the spec or the tests.
- `correction-becomes-rule`: **A correction becomes a rule**. Every correction a person makes is logged at the phase that should have caught it, and the second of the same kind becomes a check, a reviewer's rule or a line in the agent's instructions. Reads: `human-review`, `loop-outcomes`. When: Each time a person corrects the agent, in the session, in a review comment or by reverting a change; and on a schedule, when the outcome log is read for kinds that came back.
- `preview-environments`: **A preview environment for each change**. Every pull request is deployed to an environment of its own, at its own address, so the checks that need a running app test that change alone, before it is merged. Reads: `smoke-probe`, `logs`, `ci-results`. When: On every push to a pull request, once its deploy job has finished; and on a schedule, for environments of pull requests already closed.
- `architecture-fitness-functions`: **Architecture rules**. Rules for the direction of imports between layers fail as soon as the agent adds an import that breaks them, and each message describes the layers, so the agent moves the code where it belongs. Reads: `linter`, `dependency-graph`. When: After the agent adds or moves an import, at each commit, and in CI as the final run.
- `risky-action-gates`: **Ask before the irreversible**. Before an action that cannot be undone, the agent stops, and a person confirms or refuses it. Reads: `human-answer`. When: Before an action that cannot be undone, such as a deploy, a migration, deleting data, a push to a protected branch, or a message sent outside the project.
- `release-confirmation`: **Confirm the release in production**. After a release reaches production, a job judges a window of real traffic, and the change is confirmed only if production runs it, its own signal appeared often enough, and nothing is worse than under the previous version. Reads: `logs`, `metrics`, `error-tracker`. When: After each deploy to production, once a window of real traffic has passed (at least a set time and a set number of events on the changed path, up to a cap).
- `llm-evals`: **Evals on every prompt change**. After each change to a prompt, a tool description or the model, the agent runs the feature on a suite of cases several times, and a drop in the pass rate fails the change. Reads: `eval-set`, `llm-judge`. When: After each change to a prompt, a tool description, the model or a parameter the feature uses, before the agent says it is done; and in CI, on every pull request that touches one of them.
- `ci-clean-infra`: **Fix CI until it is green**. The agent pushes, CI runs the checks on clean machines, and the agent fixes what fails until every required job passes for its latest commit. Reads: `ci-results`. When: After each push, once CI has finished the run for the branch's latest commit.
- `error-tracking`: **Fix the errors users hit**. The agent takes an issue from the top of the error tracker, reproduces it with a test that fails and fixes it, and the fix counts only once the issue's events stop under the release that carries it. Reads: `error-tracker`. When: Every day, when a scheduled job collects the top new issues and the escalating ones; and after the release that carries a fix, once a window of real traffic has passed.
- `agent-code-review`: **Fresh-context code review**. Reviewer agents with a fresh context read the committed diff, and the coding agent fixes the confirmed findings for at most five rounds, each re-review checking only the open ones. Reads: `llm-reviewer`. When: After the agent's tests pass and its work is committed, before it opens a pull request; then once per round of fixes, on the fix diff.
- `api-breaking-changes`: **Keep the API compatible**. When the agent changes a schema, a library's public types or data that released clients read, a check compares the change with what callers already have, and the agent restores compatibility. Reads: `api-compatibility`. When: Before each commit that changes an interface description, a library's exports or data that released clients read; and again in CI as the final run.
- `lint-with-fix-instructions`: **Lint with fix instructions**. Every lint violation reaches the agent with a text that says how to fix it, so it fixes the cause instead of silencing the rule. Reads: `linter`. When: At each commit, and again in CI as the final run.
- `load-testing`: **Load test a preview**. The agent runs a load scenario against the preview environment of its change, and when the response time or the error rate goes over its threshold, it finds the bottleneck in the traces and fixes it. Reads: `performance-measure`, `traces`. When: After each deploy of a pull request's preview environment, in a CI job, or on a schedule against staging; the agent may also run a scenario against its own preview while it works. The traces are read when a threshold fails.
- `dependency-scanning-sbom`: **No known-vulnerable dependencies**. A scanner checks the project's dependencies against vulnerability databases, and the agent moves each vulnerable package to a safe version before the change is merged. Reads: `security-scanner`. When: On every pull request that changes a manifest or a lockfile, and every night over the SBOMs of the releases in production.
- `structured-logs`: **Read the logs**. After running a scenario, the agent queries the structured logs of its own run for errors, fixes the cause and runs the scenario again until the query comes back empty. Reads: `logs`. When: After the agent runs a scenario through the app in its worktree, before it says the work is done; and in CI, after the end-to-end job, against CI's own log store.
- `traces-opentelemetry`: **Read the traces**. After running a scenario, the agent queries the traces of its own run for spans that failed or went over budget, and fixes the cause until the same queries return nothing. Reads: `traces`. When: After the agent runs a scenario through the services it changed, before it says the work is done; and in CI, against CI's own collector and trace store.
- `third-party-extension-scan`: **Read third-party extensions before they run**. On each pull request that adds or moves the pin of a third-party plugin, skill or MCP server, a reviewer reads every file it ships against a written policy, and a fail keeps the pin out; verdicts are cached per commit and policy. Reads: `llm-reviewer`. When: On every pull request that adds an extension or moves its pin, once per new pin; and on every pull request that changes the policy, over every pinned extension.
- `red-green-tdd`: **Red, then green**. A change in behaviour starts with a test that fails for the right reason, and ends when that test and the rest of the suite pass. Reads: `test-runner`. When: Before the code for a new behaviour or a fix is written, and again after it.
- `repo-health-agent`: **Repository health**. Every day a job records the project's delivery metrics, an agent turns the worst trend into one proposed change, and a critic must approve it before it becomes a draft pull request a person reviews. Reads: `flow-metrics`, `llm-reviewer`. When: Every day, from a scheduled CI job that first records the day's metrics; the critic reads each proposed change before anything is published; and four weeks after a change merges, its metric is read again.
- `run-tests-first`: **Run the tests first**. Before changing anything, the agent runs the whole suite and keeps the result, so it never takes an old failure for its own regression. Reads: `test-runner`. When: At the start of a task, before any change; and at its end, compared test by test with that first run.
- `result-demo`: **Show the result**. Once the automated checks pass, the agent shows a person the working feature, with screenshots, a recording or the real output of a command, and the person judges the behaviour, not the code. Reads: `human-review`, `screenshot`. When: As the task's last step before the merge, once its automated checks pass; the evidence is checked in CI on the pull request.
- `health-checks-smoke`: **Smoke test after a deploy**. After each deploy to a preview environment or to staging, a job checks that the new version is ready and runs a few smoke checks against it, and a red result stops the release there. Reads: `smoke-probe`, `logs`. When: Right after each deploy to a preview environment or to staging, before the release is promoted to the next stage.
- `stall-detector`: **Stall detector**. A hook that watches every tool call tells the agent to step back when it repeats the same call or cycle five times, stops it for a person on a second stall, and keeps a subagent from starting agents of its own. Reads: `agent-activity`. When: After every tool call, and before every call that starts a subagent. A new prompt from the person starts the count again.
- `triage`: **Triage what comes in**. Each incoming error, alert, bot's pull request, user's message or ticket is merged with an open item on the same problem, or sorted as a fix, a new feature, maintenance or a question for a person, and a person decides what the judge cannot. Reads: `llm-judge`, `human-answer`. When: As each item arrives and before any work starts on it, from a webhook or a scheduled job over the error tracker, the alerts and the issue tracker. A person is asked when the judge cannot decide, and before a one-way door.
- `agentic-manual-testing`: **Try it by hand**. The agent runs what it just wrote the way a user of that code would, and turns each defect it finds into a test that fails before the fix and passes after it. Reads: `manual-probe`. When: After the agent has written a change and before it says it is done, and again after each fix. Before the turn ends, a check reads the defects found.
- `type-check-and-build`: **Type check and build**. After an edit, the agent runs the type checker and the build, and fixes each error at its file and line until both are clean. Reads: `build-and-types`. When: After each edit (the type checker, or the language server's diagnostics), and before the turn ends (the build).
- `config-validation`: **Validate the configuration**. A validator checks every configuration file and profile against its schema, a probe checks that each endpoint it names answers, and a smoke start runs the app with each profile. Reads: `structure-check`, `smoke-probe`. When: After each edit of the configuration and at each commit (the schema), on each pull request that changes the configuration (the endpoints and the smoke start), and daily (the endpoints).
- `e2e-browser`: **Walk the feature in a browser**. The agent starts the app and walks the feature through a real browser as a user would, which shows a feature broken end to end even when the unit tests pass. Reads: `browser-run`. When: After the unit tests pass on a change to a feature users reach in a browser, before the agent says it is done; and again in CI, on a fresh server.
- `fault-injection`: **When a dependency fails**. A test makes a dependency slow, time out or go down through a fault proxy, and the agent fixes retries, timeouts and error handling until the code copes. Reads: `input-fault-injection`. When: Each time the suite runs, locally while the agent works and again in CI, since the fault tests are part of it.
- `text-from-a-brief`: **Write from a brief, review once**. A text a person will decide on is written from a brief whose every fact has a source, checked against that brief and against a catalogue of plain-language errors, revised once, and then handed to a person. Reads: `llm-reviewer`, `human-answer`, `linter`. When: Whenever the agent writes a text a person will decide on: documentation, a pull request's description, release notes, a message that asks for a decision. The brief is checked before writing, the text once after it, and the revision once more for invented claims.
